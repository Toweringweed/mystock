# MyStock 分析系统 v3 升级想法

> 记录时间：2026-05-16
> 背景：在重写 stock-analysis skill 过程中产生的、值得在下一次编码升级中实现的想法。
> 这些想法目前以 Skill prompt 的方式临时解决，但在应用层面实现会更可靠、更可复用。

---

## 一、AI 收入真实性自动核查模块

**问题**：A 股大量公司在财报里把边缘业务冠名"AI/算力"。目前 Skill 里是靠分析师人工判断，无结构化数据支撑。

**想法**：
- 新增 `ai_revenue_breakdown` 表，字段：`period` / `ai_revenue` / `ai_revenue_pct` / `verification_source`（来自公告原文 / 可核实客户披露 / 仅公司自报）/ `confidence`（高/中/低）
- 通过 LLM 从季报"分部信息/经营情况分析/重要事项"章节提取，并对比投资者关系活动纪要做交叉验证
- 前端：WatchlistTable 增加"AI收入可信度"列，显示占比 + 可信度等级
- 分析报告 M2 模块自动读取此表，不再靠分析师从原始文本判断

**技术路径**：年报/季报 PDF → Playwright 下载 → PyMuPDF 提取文本 → Claude 结构化 → 入库（类似现有 `business_segments` 流水线）

---

## 二、多期限仓位逻辑分离

**问题**：一只股票对短线（1 个月）/ 中线（1-2 季度）/ 长线（1-2 年）投资者的判断可能完全不同，但现有系统只有一个综合分，无法表达这种复杂性。

**想法**：
- `claude_scores` 表增加 `horizon` 字段：`short` / `mid` / `long`
- 分析师写回时可写入 3 组不同的评分和文字
- 前端：详情页增加时间维度切换器（短/中/长），每个维度显示对应的评分卡和论点
- WatchlistTable：默认展示中线评分，可切换

**价值**：避免"短线超卖 + 长线有替代风险"这类复杂情景被强行压缩成一个数字

---

## 三、"没说什么"信号捕捉

**问题**：管理层在 IR 活动中的沉默往往比说了什么更重要（突然不再提某个大客户、不再给收入指引等），但现有系统完全忽略这类信号。

**想法**：
- 维护每只股票的"常用表述词库"（从历史 IR 纪要中提取）
- 新季度 IR 纪要入库后，自动对比：哪些之前常出现的关键词消失了？哪些是新增的？
- 生成"叙事变化摘要"，作为 `stock_events` 中的一类新事件类型：`NARRATIVE_SHIFT`
- 触发条件：关键词消失 / 新增 / 频率大幅变化

**技术路径**：LangChain 关键词追踪 + TF-IDF 变化检测 + Claude 生成叙事变化摘要

---

## 四、"定价隐含假设"自动计算

**问题**：分析师每次都要手动反推"当前 PE 隐含了什么增速"，这是机械性工作，应该自动化。

**想法**：
- 新增 `implied_assumptions` 视图或实时计算接口
- 给定当前价 + forward PE + 历史平均 PE 中枢，自动算出：
  - 隐含的 2026/2027 净利润增速（vs 一致预期的偏差）
  - 隐含的 3 年 CAGR
  - 需要增长几年才能"消化"当前估值（基于历史 PE 均值作为出口假设）
- 在 `skill-input` API 返回中增加此字段
- 分析报告 M1 自动引用，不再靠分析师手算

---

## 五、竞争对手跨市场追踪

**问题**：AI 算力链的核心竞争对手很多在美股/台股，现有系统没有结构化跟踪机制，靠 Web Search 临时查，不够系统。

**想法**：
- 新增 `peer_universe` 表，字段：`code` / `market`（US/TW/HK/CN）/ `company_name` / `related_cn_stock_id` / `relationship`（direct_competitor / upstream / downstream / global_peer）
- 定期（每周）拉取对标公司的关键指标：forward PE / 毛利率 / 季度营收增速 / 分析师评级变化
- 数据来源：yfinance（美股）+ AKShare（台股/港股）
- 分析报告 M5 同业对比表自动填充，无需手动 web search

---

## 六、Variant Perception 追踪（我的观点 vs 市场共识的历史记录）

**问题**：分析师在报告中写了"我认为市场低估了 X"，但无法追踪这个判断在后续是否被验证。缺乏反馈机制，分析质量无法迭代。

**想法**：
- 每次分析写回时，新增 `variant_perception` 字段，记录：
  - 分析师观点方向（vs 共识：高于/低于/反向）
  - 观点的具体内容（如"预计 2026 净利润比共识高 20%"）
  - 催化剂/验证时间窗口
- 季报发布后，自动回测：分析师预期 vs 实际，计算"预测准确率"
- 逐步建立分析校准记录（calibration log），帮助识别系统性高估/低估倾向

---

## 七、多空仓位建议的精细化

**问题**：现有 `price_levels` 字段有 6 个价位档（heavy_buy → exit），但生成逻辑不清晰，经常填 null。

**想法**：
- 将价位档与 M5 多情景估值表直接联动：
  - `heavy_buy` = 悲观情景目标价 × 0.9（足够安全边际）
  - `mid_buy` = 悲观情景目标价
  - `hold_low/high` = 基准情景目标价 ±10%
  - `reduce` = 乐观情景目标价 × 0.9
  - `exit` = 乐观情景目标价（已充分定价）
- 前端详情页：在 K 线图上叠加显示这 6 个价位（类似 PE Band）

---

## 八、论点失效信号的自动监控

**问题**：分析师在 M7 写了"如果毛利率连续两季跌破 30% 则论点失效"，但这个条件的触发现在完全靠人工盯，没有自动化。

**想法**：
- 新增 `thesis_monitors` 表，字段：`stock_id` / `monitor_condition`（结构化：指标/阈值/方向/持续期数）/ `linked_report_id` / `status`（watching/triggered/resolved）
- Celery 任务每季度财报入库后自动检查所有 watching 条件
- 触发时：
  - 在 `stock_events` 中生成 `THESIS_INVALIDATION_SIGNAL` 事件（severity: high）
  - 推送企业微信通知（如已配置 webhook）
  - 在 WatchlistTable 对应股票行显示红色警示标

---

## 优先级建议

| 优先级 | 功能 | 理由 |
|---|---|---|
| P0 | 四、定价隐含假设自动计算 | 纯计算，无需新表，改动最小，价值最高 |
| P0 | 八、论点失效信号自动监控 | 直接提升决策安全性 |
| P1 | 一、AI 收入真实性结构化 | A 股投资最核心的判断，自动化收益极大 |
| P1 | 七、价位档与估值联动 | 前端无需改，仅后端逻辑完善 |
| P2 | 二、多期限仓位分离 | 需要前端+后端双改，但价值高 |
| P2 | 五、竞争对手跨市场追踪 | 需要新数据源接入 |
| P3 | 三、叙事变化捕捉 | 技术难度高，但差异化价值大 |
| P3 | 六、Variant Perception 追踪 | 需要积累足够历史数据才有意义 |
